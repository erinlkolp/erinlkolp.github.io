Notes for Claude working in this repo.

## Stack

- Astro 4.16 (static site, MDX content collection)
- Tailwind for styling, JetBrains Mono via `@fontsource`
- Vitest for unit tests of `src/lib/` (Node-side code only — Astro components are not unit-tested; rely on `npm run build` for integration)
- Deploys to GitHub Pages via Actions on push to `main`

## Commands

    npm run dev      # local dev server (default :4321)
    npm run build    # astro check + astro build
    npm test         # vitest

`npm run build` runs `astro check` first, so TypeScript errors fail the build.

## Layout

- `src/pages/` — routes
- `src/layouts/` — `BaseLayout`, `BlogPostLayout`
- `src/components/` — small Astro components
- `src/content/blog/*.mdx` — blog posts (collection schema in `src/content/config.ts`)
- `src/content/blog/_template.mdx` — starter file; the `_` prefix means Astro's content loader skips it, so it never publishes
- `src/assets/blog/<slug>/` — per-post image folder
- `src/lib/` — TS modules (e.g. GitHub fetch); these are what vitest tests
- `tests/` — vitest test files
- `docs/` — gitignored. Specs live at `docs/superpowers/specs/`, plans at `docs/superpowers/plans/`

## Writing a blog post

Per-post folder layout:

    src/content/blog/<slug>.mdx
    src/assets/blog/<slug>/<image>.png

Quick start:

    SLUG=my-new-post
    cp src/content/blog/_template.mdx src/content/blog/$SLUG.mdx
    mkdir src/assets/blog/$SLUG

Then in the new `.mdx`:

- Fill frontmatter (`title`, `description`, `pubDate`, `tags`).
- Replace `REPLACE-WITH-POST-SLUG` with the slug in every `<PostImage>` call.
- Set `draft: false` when ready.

`<PostImage>` props:

| Prop      | Required | Notes                                            |
| --------- | -------- | ------------------------------------------------ |
| `slug`    | yes      | Must match the folder under `src/assets/blog/`   |
| `src`     | yes      | Filename only, no path                           |
| `alt`     | yes      | Required by Astro's `<Image>`                    |
| `caption` | no       | Defaults to `src` (the filename)                 |

Missing images fail the build with `Image not found: src/assets/blog/<slug>/<src>`.

## Conventions

- Filenames starting with `_` are excluded from Astro content collections — keep using this for templates/drafts that should not publish.
- The blog index and post route both filter `!data.draft`.
- `src/env.d.ts` is auto-generated by Astro on first build; it shows up untracked. Leave it alone.
- `docs/` is gitignored on purpose — specs and plans there are working notes, not part of the deliverable.
